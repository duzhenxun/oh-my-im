# 消息到回复链路

## 共同链路

两条入口都将外部消息转成 prompt，经 `runCodex` 调用本机 `codex exec --json` 或 `codex exec resume --json`，解析 JSONL 中的会话、文本和工具调用，再把结果送回钉钉。见 [[topics/模块边界|模块边界]]。

## 入口差异

| 环节 | 机器人 Stream Mode | DWS 群监听 |
| --- | --- | --- |
| 入站 | `dingtalk-stream` 的 `TOPIC_ROBOT` 回调 | `dws event consume user_im_message_receive_group_all`，另有轮询补偿 |
| 允许条件 | 单聊且 sender 在 `botAllowedUserIds` | 消息匹配 `groupId + senderId` 规则；监控命令仅允许指定用户 |
| 并发 | 同一 DingTalk 会话只运行一个任务 | 每群一个队列，期间新消息合并为下一批 |
| 会话键 | `conversationId` | `groupId`，内存中保存 |
| 主要回复 | 互动卡片；缺少 `robotCode` 或卡片失败时回退 `sessionWebhook` 文本 | 正常 Codex 批次只更新互动卡片；卡片失败仅记录错误。AI 启停命令单独发送普通机器人文本 |

## 安全与限制

- 静态实现中两种 `codex` 配置都使用 bypass 权限；DWS prompt 还明确要求外部群消息不能绕过下游 Skill 的环境与确认门禁。
- 单聊 Stream 模式依赖本地凭证和授权名单；群模式依赖 DWS 登录态、群/人员规则与卡片机器人配置。
- “事件连接”或子进程启动只说明链路的一部分；实际成功必须看消息被消费、Codex 完成及钉钉回复成功的完整证据。
