# oh-my-im 系统图谱

```text
omi CLI (src/omi.ts)
  |-- listener mode --> DWS listener (src/dws-listener.ts)
  |                         |-- dws event consume + polling --> configured group/person rules
  |                         |-- monitor command --> dashboard config
  |                         |-- Codex runner --> interactive card
  |                         `-- monitor command --> DWS bot text confirmation
  |                         `-- local dashboard --> browser configuration/status
  `-- bot process -------> Stream bot (src/omi-bot.ts -> src/index.ts)
                            |-- DingTalk Stream callback --> whitelist + session serialization
                            |-- media download / command handling
                            `-- Codex runner --> interactive card or sessionWebhook text reply

Shared: src/codex.ts, src/config.ts, src/dingtalk-card.ts, src/logger.ts
Persistent user state: ~/.oh-my-im/ (configuration, locks, card/reply/process state)
```

## 关系说明

- [[topics/入口与运行模式|Omi]] 是进程管理器，默认同时拉起群监听和单聊机器人；`--no-listen` 仅启动机器人。
- [[topics/DWS群监听|DWS 群监听]] 与 [[topics/机器人Stream模式|机器人 Stream Mode]] 是两条不同的入站通道，均调用 [[topics/模块边界|Codex runner]]。
- [[topics/配置与状态边界|管理页]] 服务于 DWS 监听器，但其保存的应用凭证亦被单聊机器人读取。
- [[syntheses/消息到回复链路|消息到回复链路]] 记录消息、处理、会话和回复的条件分歧。

## 待验证

图中外部边界来自静态实现。当前 DWS 事件消费、DingTalk API 权限、交互卡片和 Codex CLI 是否可用，须以实际探针和返回结果确认。
